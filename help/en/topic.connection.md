---
title: Connection
short: How the app connects to the batteries: via a USB-RS485 adapter or an RS485-to-Ethernet gateway (TCP).
related: topic.buses
---
- **Installation:** before connecting you choose the installation at the top. Everything the app stores (recording, serial numbers, parameter states, cell types, groups) then belongs to it. A USB port never changes the choice, since the same adapter moves between banks. A gateway that belongs to exactly one active installation chooses it by itself; if it belongs to several, the chosen one stays when it is among them, otherwise the app asks you to choose. A new endpoint is linked to the chosen installation when connecting (one line, no dialog). While connected the choice and the connection fields (network/USB, address or port, bus, packs) are fixed; to change them, disconnect first. The automatic reconnect uses them too.
- **View only:** for a quick look at a foreign bank. Nothing is stored (no recording, no serial numbers, no parameter states) and nothing is written to the packs.
- **Right bank:** after connecting the app reads the serial numbers and compares each pack's BMS serial number (String 2) with the chosen installation. New or moved boards are named in a line with “Yes, take over”; a board of another installation in a red line with “Disconnect” and “Connect with “B”” (disconnects, chooses B and connects again). On RS485-1/2 recording (and linking a new endpoint to the installation) starts only once the serial numbers confirm the bank: a pack the installation knows, packs without a serial number, or all reads ended without a result. If the installation knows none of the packs, it starts only after “Yes, take over”. Until then it says “Recording waits for the installation check”; on the CAN socket String 2 is not visible, there the app only compares the master's battery serial number and keeps recording. Packs without a serial number cannot be assigned (see Installations).
- **Network (TCP):** gateway address as `host:port`, e.g. `192.168.1.10:4196`. The baud rate is configured on the gateway (CAN socket 9600, RS485-1/2 19200).
- **USB/serial:** select the adapter's port; the baud rate follows the selected bus.
- **Check when connecting:** “Connect” first asks addresses 0–15 with 0x51 (the ones to be polled first) and counts as connected only when a pack answers; on the CAN socket the master's Modbus answer is enough. If nothing answers, the app stays disconnected and says what it heard: nothing, unreadable data (usually a wrong baud rate) or a master polling its slaves. On a USB port it then tries the other bus's baud rate; if a pack answers there, “Connect via …” switches with one click. A gateway has its baud rate set, so the app names what to check. A pack in its bootloader or shortly after a restart (about 5 s) does not answer either. An endpoint where nothing answers is not linked to an installation and not recorded.
- **Order after connecting:** on the CAN socket the app first reads the master's system values (Modbus) and shows them at once. If the master reports its slave count (only with the maintenance firmware, command 0x64), the app polls exactly these packs without a search. Otherwise the **Packs** setting applies: a fixed number starts polling addresses 0 to number−1 at once, “search” scans addresses 0–15. Then all packs are polled every 2 s; names and firmware versions follow shortly after the start. While the master's maintenance mode is active it reports 0 slaves; then the app searches.
- Without a valid answer for **60 s**, the connection counts as lost (“Connection lost”). If the gateway closes the connection or it fails with an error, it counts as lost at once. The app then reconnects automatically every 30 s until packs answer again.
- Only one program may poll the bus at a time. If e.g. the Home Assistant add-on uses the same gateway, requests collide.
