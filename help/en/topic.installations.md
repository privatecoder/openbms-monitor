---
title: Installations
short: Everything the app knows about a bank belongs to an installation. The Installations view lists them with their packs.
related: topic.connection, topic.history, topic.params, topic.maintenance
---
- **What belongs to it:** the recording, the boards identified per address, the cell type per pack, groups and pairs, the diagnosis, the parameter states and the update logs. User cell models stay shared by all installations.
- **Choose:** in the sidebar before connecting (see Connection). Without a connection the chosen installation decides what History and Parameters show; the overview always shows the bus actually connected.
- **Boards:** the BMS serial number (String 2) identifies a board. If the installation knows it at this address (also as an earlier board there), it is recorded as seen. A board the installation does not know at this address yet is not recorded at first: the sidebar says “This installation does not know the boards at 00, 03 yet (new or moved)”, and only “Yes, take over” records them (one confirmation for all packs of the connection, also for a new installation). Then the app says “Another board at address 07?” and keeps the old one as “previous board”; its parameter states no longer count as the current state. Empty, placeholder or no answer: “unclear”, nothing is claimed.
- **Right bank:** if a board read (or the master serial) belongs to another installation, also an archived one, a red line says “Pack 02 belongs to installation “B”. Is another bank connected here?” with “Disconnect”, “Connect with “B”” and “Take over … anyway” (for a board that really moved; the other installation keeps its history). While that is open, the app stores nothing for this connection under the chosen installation (no recording, no parameter states). Before every write (parameters, clock, CAN protocol, calibration, serial number, control) it reads String 2 of the target pack again: a board not taken over, or a pack that does not answer, gets nothing written. If the pack has no serial number, it writes with the note “installation not checked (board without a serial number)”.
- **Setting serial numbers:** the serial numbers identify the bank. Without them (self-built packs, factory placeholder) the app cannot tell banks apart; the sidebar names such packs. Set them under Parameters → Serial numbers, a unique one per pack. Setting the battery serial number (String 1) as well is worth it: it is the only one the CAN socket shows (master only, over Modbus, the first 22 characters, firmware 16.06.11 or later); “Use BMS number” puts String 2 into its field. When the app writes String 2 itself, it stays the same board. The cell type belongs to the address, since the cells stay when the board is swapped.
- **Taken over:** earlier versions kept data by endpoint (gateway address or port). Each such endpoint becomes once an installation of its own with its name, marked “taken over”, even if the endpoint already belongs to an installation: the same adapter may have served two banks, and mixed data cannot be separated afterwards. If the endpoint belongs to exactly one installation, the card offers “Merge with installation X”.
- **Merge:** adds, never overwrites. What the target installation has set (a pack's cell type, groups, pairs, diagnosis) stays; the other values are kept in the log of the move. Two recording rows of the same pack at the same time: the target's stays, the other is counted. The merged installation is gone afterwards.
- **Archive:** keeps everything; the installation is just no longer offered and never chosen by itself. “Bring back” undoes it.
- **Delete:** only without open work (no marker on, no pack in its bootloader) and not while the app is connected with it. Before, the app lists what goes (recording, boards, parameter states, cell types, groups, diagnosis). Update logs stay as files and are then listed under “Logs without installation”, like all logs from before installations; the app does not assign them by guessing.
- **Pack table:** per address the current board (and the previous one after a swap), the cell type, the last parameter state (a click opens it under Parameters) and the last update with image, result and log.
- **Export and import:** in an installation's card, “Export …” saves a ZIP file with boards, cell types, groups and pairs, diagnosis, all parameter states and the update logs; the recording (values and messages) only on request. “Import installation …” checks the file first (only known entries, checksums) and shows what it holds and where it goes: into the same installation, as a new one or, with the same master serial number, into an existing one. If the master serial number differs for the same installation, “as a copy” is preselected. An import overwrites nothing and duplicates nothing; the same export a second time changes nothing. Endpoints are not taken over. If an import stops, “Resume” finishes it; until then the target installation can be neither deleted nor merged.
