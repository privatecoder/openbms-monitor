---
title: Writing parameters and serial numbers
short: Change a pack's parameters and write them, bring a pack in line with the others, write the same change to several packs, set serial numbers. Via the RS485-1/2 bus; parameters with patched firmware (from MAINT 1.5.2/1.6.3) also via the CAN socket.
related: topic.params, topic.paramCheck, topic.switches, topic.firmware
---
- **Edit:** after reading, every pack column has a pencil. The column's cells become inputs (values in the unit shown, switches as check boxes); only one column is edited at a time. Changed cells are coloured, the bar above the table lists the changes.
- **Bring a bank in line:** “Take values from …” fills the column with all values and switches of another column (another pack or an opened BatteryMonitor export). Single values can still be changed afterwards. The way: read all packs, edit one, take from the reference pack, write, next pack. Exports with a shifted order are not offered.
- **Input:** every value is rounded to the resolution the BMS stores it in (e.g. 1 mV, 10 mV, 0.1 °C, 0.01 A); after leaving the field it shows the rounded value.
- **What the app checks before writing**, only against concrete harm: a readable number inside the storable range; the number of cells in series (P65) stays until you unlock it in the bar (a wrong count makes every cell protection wrong); and the rules the BMS itself checks a block with, e.g. “recovery ≤ alarm”, cell voltages 2.000–4.300 V, temperatures −30 to 80 °C, currents up to 300 A. If one is broken, the bar names it and the button stays off. Equality is allowed. The BMS checks neither the function switches nor the chemistry.
- **Datasheet:** with a cell type chosen, the bar names changed values outside the datasheet. That blocks nothing.
- **Full capacity:** after every successful write the BMS compares the learned full capacity with the rated capacity (P58). If they are 10 Ah or more apart, it sets the full capacity to P58 and the SOC jumps; this happens even when P58 was not changed. The bar says so beforehand and offers to set P58 to the learned full capacity.
- **Writing:** the app reads the pack once more right before. If a value you did not touch has changed since, it does not write and shows the current state; your changes stay. Otherwise it sends the whole block (device name unchanged), reads it back and marks in red what was not taken. If the BMS's answer to the write is missing, the app reads the block afresh: if it shows the values sent, the write counts as done (“answer missing, read-back confirmed”), if it shows the previous ones, as not reached; otherwise it says “Result unclear: please read the parameters again”, and a series over several packs stops at that pack. New limits apply at once: MOSFETs, balancing, heating and the CAN limits may switch the next moment.
- **Via the CAN socket (patched firmware):** before every write the app reads the target's BMS serial number via the CAN socket and writes only when everything fits: the same board as when the column was read, listed in this installation at exactly this address, unique (not empty, not the placeholder, no unusual characters) and listed at no other address. Otherwise the bar names the reason and nothing is written. A board whose identity was stored before this check is taken over once in the sidebar. If the same board is still listed at an old address, the app sorts it out itself when another board answers there; if no checkable board answers there, mark the old entry as no longer present explicitly. Clock, CAN protocol, serial numbers, calibration and control stay on the RS485-1/2 bus.
- **To other packs:** “Also to other packs …” in the bar picks further packs that were read on this connection (unread ones are greyed out with “read first”; “all read” picks them all). What is written is the **change**, not the column: every pack gets exactly the changed values and switch bits on top of its own read state, everything else (P58 and the other switches, too) stays its own. Every target is checked with the same rules; a pack that breaks them, already has the values or has a pending refusal is skipped, with the reason. Before that the app reads every pack's learned full capacity and names in the one confirmation for which packs the write resets it to P58. Then it writes one after another: the edited pack first, then the others by address, each like a single write (fresh read, write, read back). If the connection or installation changes or you press “Cancel”, it stops before the next pack. If a pack refuses and switches became active doing so, the series halts there: restore first, then “Go on with the other packs” or “Cancel”. Below, every pack's line says what happened.
- **Refused:** if the BMS still refuses the block (other firmware, other rules), its function switches are already active but not stored. The bar shows which, and “Restore stored switches” writes back the state from before the attempt. The app repeats nothing on its own, because every write can reset the full capacity. A restart of the pack restores the stored switches, too. Until the stored state is read again, the app writes nothing else to this pack.
- **History:** every read and write is kept per installation, pack and board (told apart by String 2) in the app's database `maintenance.sqlite`; clearing the recording leaves it. States of a previous board at the same address do not count. With “View only” nothing is kept and nothing written. The column shows “last written”; the clock symbol loads the state from before the last write into the edit, to write it back with the same checks.
- **Device name:** the name in the parameter block (at most 10 characters, printable ASCII). RS485-1/2 only: the app reads the block fresh, writes only while the pack still holds the name shown, replaces the name alone and reads back. Like every parameter write this sets the learned full capacity to P58 when the two differ by 10 Ah or more; the app says so before. The BMS also reports the name to the display and to Pylontech and Modbus queries.
- **Serial numbers:** below the CAN protocol line, for the chosen pack. String 1 is the battery serial number (reported by the master over Modbus and to the inverter), string 2 the serial number of the BMS board. Allowed are 1–30 printable ASCII characters; the BMS stores them at once, the app reads them back. The BMS has no password like BatteryMonitor's. The app writes String 2 only when it could read the old value before: that is how it knows the board stays the same. String 1 of a known board is stored for it right after the read-back, so the check of the master at the CAN socket still matches; if storing fails, the app says so.
- **Master serial:** before flashing, the app checks that the right bank is on the port, by string 2 of the master (address 0). If you write a new value there and the old one was the installation's master serial, the app stores the new one. If the app stops exactly in between, the check reports another bank; “take over the serial number” in the maintenance panel resolves that.
